## 4. Requisitos aprovados

- **Igrejas:** Admin Distrital cadastra igrejas; cada igreja tem seus departamentos.
- **Departamentos padrão (8):** Recepção, Diaconato, Limpeza, Louvor, Pregadores, Escola Sabatina, Sonoplastia, ANP (+ Agenda Pastoral).
- **Agenda Pastoral:** **um único pastor no distrito — Pr. Erivando** (06/10); o grupo se chama **PASTOR DISTRITAL**.
- Departamentos são **cadastráveis/editáveis pelo admin** (nome, cor, sigla) — não fixos, com **IDs estáveis** para não quebrar permissões ao renomear.
- **Sigla** prefixada no evento (`Preg_Altair Farina`) quando **2+ agendas** estão marcadas — *pergunta em aberto: mostrar sempre ou só com 2+?*
- Eventos em **texto livre** (sem campos estruturados) — preenchimento simples (clique no dia → escrever → salvar).
- **Colunas:** DOM, QUA, SÁB com mesma largura (maior); SEG/TER/QUI/SEX menores, com opção de **ocultar**.
- Sem cor de fundo "pintada" nos dias destacados com tom quente — **revertido**; usar o azul-marinho sutil (seção 3).
- Cabeçalhos com dias por extenso: DOMINGO, SEGUNDA, TERÇA, QUARTA, QUINTA, SEXTA, SÁBADO.
- **Arrastar e soltar** eventos entre dias.
- **Todos os eventos visíveis** por dia (sem limite "+N mais…" — removido a pedido).
- **4 níveis de acesso:**
  - `admin_dist` – Admin Distrital: edita tudo, cadastra igrejas/usuários
  - `admin_local` – Admin Local: edita só a própria igreja, cadastra usuários nela
  - `membro` – Membro/Líder: edita só o próprio departamento
  - `visitante` – **Membro** (rótulo trocado de "Visitante", 06/10): só visualiza, filtra e imprime; **não troca de igreja** (seletor escondido + guarda no código)
- **Usuário "membro" por igreja** (06/10): criado automaticamente — `login: membro`, `senha: membro123`, nível Membro, na própria igreja; nasce junto em toda igreja nova e migra ao renomear. Por isso **login duplicado só é bloqueado dentro da mesma igreja** (mesmo login pode se repetir em igrejas diferentes).
- **Seleção de igreja a cada login** (escolhe ao entrar; pode trocar no topo — **exceto no nível Membro**, que fica fixo na igreja própria).
- **Impressão / PDF:** A4 paisagem com cabeçalho (igreja, mês, data) + CSS de impressão.
- **Responsivo** (computador e celular), navegação por teclado `←/→`, ESC fecha modais.
- Login real: admin registra **nome, usuário, WhatsApp, senha, igreja, departamento(s), nível** — sem autorregistro. (Cadastro em formulário já existe no protótipo; falta backend.)
- **Lista de Oficiais (definido e implementado 06/10):** módulo com **dados digitados** (Departamento | Cargo | Responsável — **3 colunas, sem Contatos**, decisão do usuário), cabeçalho com igreja + data base, departamento aparece uma vez por grupo (linhas seguintes em branco, como no PDF), busca, impressão A4 no formato do PDF original. Permissões: Admin Distrital edita em qualquer igreja, Admin Local só na sua, Membro só visualiza a própria. **+ botão "📎 Anexar PDF oficial"** (arquivo para baixar — decisão do usuário 06/10): o PDF é **anexo complementar, não substitui a lista digitada** (é a lista que permite busca, impressão e atualização).
  - *Fonte:* `oficiais2026.pdf` (2 págs., 19 departamentos, **73 oficiais**, Data Base 06/10/2026, igreja Jardim Kakimori).
  - *Decisões do usuário (06/10):* **sem a coluna Contatos** (só 3 colunas) e **importar os dados extraídos** para a Jardim Kakimori — feito, a semente já vem no `index.html` (as demais igrejas começam vazias). **Admin Local pode importar o PDF oficial da própria igreja** (fica guardado por igreja) e o anexo aparece **na impressão** como linha do cabeçalho.
- **Programação (definido e implementado 06/10):** cada igreja lança a programação do seu culto (domingo, sábado, quarta, semana de evangelismo…). Uma programação = **cabeçalho** (título + quando + data opcional + observação) + **linhas** com **Bloco · Horário · Atividade · Responsável** — *decisões do usuário:* as 4 colunas com o **bloco como faixa azul** (como no exemplo da planilha: "Escola Sabatina", "Culto Divino") e **dia da semana + data opcional** para eventos pontuais. Itens **ordenados por horário**; horário aceita `09h05` e `09:05` (normaliza para `09h05`). Busca por título/atividade/responsável; **colar do Excel** (linha com horário = atividade; linha só com texto = faixa de bloco; 4 colunas também servem); impressão A4 com a mesma cara da planilha. Permissões iguais aos oficiais: Admin Distrital em qualquer igreja, Admin Local só na sua, Membro só visualiza/imprime.

## 5. Decisões técnicas

- **Armazenamento em nuvem: Supabase** (escolhido pelo usuário sobre Firebase/localStorage).
- **Hospedagem:** sem domínio próprio; começar em host grátis (Netlify/Vercel) e migrar depois. Domínio proposto `escalas.distrital.com.br` indisponível (não há domínio registrado).
- Protótipo atual: **1 arquivo só**, JS vanilla, dados em memória (seed por mês/igreja) — serves para validar a interface antes do backend.
- **Virada para o Supabase — destino dos dados do protótipo (decisão do usuário, 07/10):** o banco **nasce limpo**; **nada** do `localStorage` migra sozinho (as escalas de teste da semente e o que ele criou brincando ficam para trás). Junto, deixar um **botão/script opcional "carregar dados de demonstração"** — serve para testar/mostrar o sistema sem sujar os dados reais (recarrega a semente de 7 igrejas/escalas/usuários só nesse modo).
